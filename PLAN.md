# Малкото Умниче — План за разработка

> Образователна PWA за деца 2–6 г. Безплатна, без реклами, без абонаменти, офлайн.
> Източник: `ИДЕЯ ЗА ДЕТСКА ПЛАТФОРМА С ПЪЗЕЛИ И ИГРИ.docx` + `gamification-skills-main`

---

## 1. Заключени решения

| Тема | Решение |
|---|---|
| Стек | Vite + React 18 + TypeScript |
| Състояние | Zustand (~1KB) |
| Persistence | IndexedDB (idb-keyval) |
| Офлайн | vite-plugin-pwa, precache на всичко |
| Валидация | Zod, на build-time за всяка активност |
| Език | Само BG, но целият текст минава през i18n слой |
| Илюстрации | **Осигуряват се от собственика на проекта.** Кодът работи с placeholder генератор |
| Аудио UI | Синтезирано през WebAudio (0 байта) |
| Аудио музика | 4–6 лупа, свалят се ръчно по спецификация |
| Изследване | Каталог от знание + точкова уеб проверка |
| Бекенд | Няма. Всичко е локално на устройството |

## 2. Продуктови принципи (не се нарушават)

1. **Ученето е В механиката.** Никога куиз след играта. Ако детето може да „изиграе" активността без да научи нищо — активността е счупена.
2. **No-fail за 2–4 г.** Няма „грешно". Грешен елемент се връща плавно с мек звук. Понятието „грешка" се въвежда от 5 г. нагоре.
3. **Нула социално сравнение.** Няма класации, няма PvP, няма „други деца".
4. **Нула загуба.** Няма streaks, няма изгарящ прогрес, няма отнемане. Прогресът само расте.
5. **Нула времево напрежение** по подразбиране. Опционален таймер само за 7–8 г.
6. **Мек стоп.** Изтичащото време се обявява 60 сек предварително с анимация за приключване, не с рязко заключване.
7. **Родителят е потребител №1.** Детето използва продукта; родителят го избира. Всяка активност има бележка защо е полезна.
8. **Достъпност не е екстра.** Тап-таргет 88px (2–4 г.) / 72px (5–6 г.) / 56px (7–8 г.), абсолютен под 48px навсякъде; никога само цвят като носител на смисъл; `prefers-reduced-motion` уважен; работи без звук.

### Приложение на gamification скиловете

**Взето:** Flow theory (адаптивна трудност), Juicy feedback (8-те характеристики), „Chocolate-covered broccoli" принципът, D6 моделът за дизайн на активност, Octalysis drives 2 / 3 / 4 / 7.

**Изхвърлено съзнателно:** leaderboards, PvP, Drive 6 (Scarcity), Drive 8 (Loss & Avoidance), социален натиск. Тези са проектирани за класни стаи с тийнейджъри и са контрапродуктивни при 2–8 г.

## 3. Архитектура

```
src/
  app/              шел, рутиране, providers, error boundary
  design-system/    tokens.css, примитиви (Button, Card, Sheet, Confetti…)
  engines/          20 двигателя; всеки = схема + компонент
    <engine>/
      schema.ts     Zod схема на params
      Engine.tsx    компонентът
      index.ts      регистрация
  content/
    schema/         Activity схема, Skill/Theme енумерации
    activities/     JSON файлове — истинското съдържание
    generators/     seeded генератори (лабиринт, шарка, редици…)
    packs.ts        тематични групи
  assets/
    manifest.ts     регистър на asset id → файл
    placeholder/    процедурни SVG заместители за липсваща графика
  kid/              детски екрани (tap-first, едър, без текст където може)
  parent/           PIN-защитен панел (професионален, плътен с информация)
  core/
    store/          настройки, профили, сесия
    persistence/    IndexedDB слой
    audio/          WebAudio SFX синтез + музикален плеър
    time/           бюджет на екранно време, мек стоп, пауза
    adaptive/       рейтинг по умение → избор на трудност
    a11y/
  i18n/             bg.ts + типизирани ключове
docs/
  mechanics/        каталогът от 100 механики (JSON + четима страница)
  ASSETS.md         спецификация за илюстрациите
  DESIGN-BIBLE.md   правилата за всяка бъдеща активност
  AUDIO.md          списък и спецификация за музикалните лупа
```

### Договор: двигател

```ts
export type Engine<P> = {
  id: EngineId;
  paramsSchema: z.ZodType<P>;
  minAge: number; maxAge: number;
  Component: FC<EngineProps<P>>;
};

export type EngineProps<P> = {
  params: P;
  api: EngineApi;                       // sfx, celebrate, hint, speak, haptic
  onComplete: (r: Result) => void;
};
```

### Договор: активност (един JSON = една активност)

```jsonc
{
  "id": "matching-farm-sounds-01",
  "engine": "matching",
  "schemaVersion": 1,
  "titleKey": "act.matching.farmSounds",
  "ageMin": 3, "ageMax": 5,
  "difficulty": 2,                       // 1–5
  "skills": ["visual-perception", "vocabulary", "attention"],
  "durationSec": 90,
  "theme": "farm",
  "assets": ["animal.cow", "animal.sheep", "animal.duck"],
  "params": { /* валидирано от схемата на двигателя */ },
  "parentNoteKey": "note.matching.farmSounds",
  "a11y": { "colorIndependent": true, "requiresAudio": false }
}
```

**Правило:** нова активност = нов JSON. Ако добавянето на активност изисква писане на код, значи трябва нов двигател — а не хак в стар.

### Генератори

За двигатели с комбинаторно съдържание (лабиринт, шарка, редици, броене, математика) активността носи `generator: { kind, seed, ...knobs }` вместо изброено съдържание. Един JSON → безкрайни вариации. Това е реалният път до 500+ активности.

### Placeholder система за графика

Тъй като илюстрациите идват отвън, `assets/placeholder/` генерира процедурен SVG за всяко неразрешено `asset id` — разпознаваема форма + етикет + стабилен цвят от хеша на id-то. Приложението е напълно играбилно от ден 1; истинската графика е drop-in подмяна в `manifest.ts`.

## 6. Дефиниция на „готово" за активност

Активността е готова само когато:

- ✅ валидира срещу схемата на своя двигател
- ✅ има родителска бележка
- ✅ има деклариран a11y профил
- ✅ работи без звук
- ✅ работи без цветово зрение
- ✅ има no-fail поведение, ако `ageMin ≤ 4`
- ✅ завършва под декларираното `durationSec`
- ✅ използва само asset id-та, регистрирани в манифеста

## 7. Рискове

| Риск | Смекчаване |
|---|---|
| Илюстрациите закъсняват | Placeholder система — разработката не спира нито ден |
| Договорът двигател↔активност се пропуква | Zod + build-time валидация; правилото „нов JSON или нов двигател, никога хак" |
| Bundle расте с 20 двигателя | Lazy loading по двигател; перф бюджет в CI |
| Съдържанието остава плитко | Генераторите носят обема, не ръчните JSON-и |
| Дизайнът се разминава между активностите | DESIGN-BIBLE.md + споделени примитиви, нула локални стилове |
